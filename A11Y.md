# NGXSMK Accessibility (A11y) & Interaction Specification

> **Target Standard**: WCAG 2.2 Level AA / Level AAA  
> **Philosophy**: Accessibility is not a compliance checkbox; it is NGXSMK's defining competitive advantage. Every component is engineered for keyboard navigation, screen reader clarity, high-contrast legibility, and reduced-motion ergonomics.

---

## 1. Universal Keyboard Interaction Matrix

Every interactive component in NGXSMK implements predictable keyboard navigation:

| Component Category | Activation Key | Navigation Keys | Dismissal / Back |
|---|---|---|---|
| **Buttons & Triggers** | `Enter`, `Space` | `Tab`, `Shift+Tab` | — |
| **Menus & Context Menus** | `Enter`, `Space`, `ArrowDown` | `ArrowDown`, `ArrowUp`, `Home`, `End` | `Escape`, `ArrowLeft` (submenus) |
| **Select / Combobox** | `Enter`, `Space`, `ArrowDown` | `ArrowDown`, `ArrowUp`, Type-ahead | `Escape`, `Tab` |
| **Tabs (`role="tablist"`)** | `Enter`, `Space` (or auto-select) | `ArrowRight`, `ArrowLeft`, `Home`, `End` | — |
| **Accordions & Disclosures** | `Enter`, `Space` | `ArrowDown`, `ArrowUp`, `Home`, `End` | — |
| **Dialogs & Modal Sheets** | — | `Tab`, `Shift+Tab` (Trapped) | `Escape`, Close Button |
| **Sliders & Range Sliders** | — | `ArrowRight`/`ArrowUp` (+1 step), `PageUp` (+10%), `ArrowLeft`/`ArrowDown` (-1 step), `Home` (min), `End` (max) | — |
| **Data Tables** | `Enter` (sort/select) | `ArrowKeys` (cell roving), `PageUp`, `PageDown` | — |
| **Tree Views** | `Enter`, `Space` | `ArrowDown`, `ArrowUp`, `ArrowRight` (expand), `ArrowLeft` (collapse) | `Escape` |
| **AI Composers & Chat** | `Enter` (Submit), `Shift+Enter` (New line) | `ArrowUp` (edit previous prompt) | `Escape` (clear/cancel) |

## 2. Focus Management & Roving Focus Architecture

### 2.1 Roving Focus Group (`@ngxsmk/cdk/roving-focus`)
- Keeps a single item in the tab sequence (`tabindex="0"`) while all other sibling items have `tabindex="-1"`.
- As the user presses Arrow keys, `tabindex="0"` moves synchronously with DOM focus.
- Remembers the last focused item when the user tabs away and returns.

### 2.2 Focus Trap Primitive (`@ngxsmk/cdk/focus-trap`)
- When a modal dialog, drawer, or command palette opens:
  1. The previously focused DOM element is recorded.
  2. Focus is shifted to the first focusable element inside the modal (or the modal container).
  3. Pressing `Tab` from the last focusable element wraps back to the first; pressing `Shift+Tab` from the first wraps to the last.
  4. Upon closing (`Escape` or backdrop click), focus is restored immediately to the trigger element.

### 2.3 Skip Links (`@ngxsmk/cdk/skip-link`)
- Placed as the first child of `<body>` or root `<app-root>`.
- Allows keyboard users to bypass top bars and sidebars, jumping directly to `<main id="main-content">`.

## 3. Screen Reader Semantics & Behavior Matrix

| Component | ARIA Role | Dynamic Attributes | Announced State Changes |
|---|---|---|---|
| **Dialog / Modal** | `role="dialog"` | `aria-modal="true"`, `aria-labelledby`, `aria-describedby` | Focus entry announcement, dialog title & description readout. |
| **Toast & Alerts** | `role="status"` / `role="alert"` | `aria-live="polite"` (toasts) / `aria-live="assertive"` (errors) | Screen readers announce new messages without shifting keyboard focus. |
| **Dropdown Menu** | `role="menu"` | `aria-haspopup="true"`, `aria-expanded="true/false"` | Announces item count, menu open/close status, and current selected option. |
| **Tabs** | `role="tablist"`, `role="tab"`, `role="tabpanel"` | `aria-selected="true/false"`, `aria-controls="panel-id"` | "Tab 2 of 4, selected". |
| **Checkbox / Switch** | `role="checkbox"` / `role="switch"` | `aria-checked="true/false/mixed"`, `aria-disabled="true"` | "Dark mode, switch, on". |
| **Progress / Meter** | `role="progressbar"` | `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-valuetext` | "Uploading file, 64%". |
| **AI Stream / Chat** | `role="log"` | `aria-live="polite"`, `aria-busy="true/false"` | "AI is thinking..." ➔ Text stream readout upon completion. |

## 4. Visual Contrast & Windows High Contrast Mode

- **WCAG 2.2 AAA Contrast**: All standard body copy meets or exceeds **7:1** contrast; all interactive controls and large text meet **4.5:1** contrast.
- **Dual Focus Rings**: Focus rings use `--ngxsmk-focus-ring` with high-contrast inner border offsets to ensure visibility over pure white, deep black, or vibrant primary backgrounds.
- **Forced Colors Mode (`@media (forced-colors: active)`)**:
  - Outlines are explicitly rendered via `outline: 2px solid Highlight`.
  - Icon buttons, focus rings, and active selection indicators use standard system color keywords (`ButtonText`, `Highlight`, `Canvas`).

---

## 5. Touch Target Sizing (WCAG 2.2 Success Criterion 2.5.8)

- All interactive controls have a minimum target size of **44×44px** (`--ngxsmk-touch-target-min`) on touch devices.
- Close buttons on badges, tags, chips, and toast items utilize negative margin hit-box expansions (`padding: var(--ngxsmk-space-2)`) to satisfy target dimensions without bloating visual density.
